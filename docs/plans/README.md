## Phase 1 — deviations from reference

Intentional deviations from the reference repo (https://github.com/jimprosser/obsidian-web-mcp) noted while porting the tool surface (spec §5), recorded per Task 15's parity spot-check:

- **`vault_search` is literal, not regex.** The reference's search accepts arbitrary patterns; ours does a case-insensitive (by default) literal substring match. Avoids ReDoS from untrusted query strings and keeps behavior predictable for an LLM caller; `pathPrefix` scopes the search instead.
- **Vault timezone is an explicit setting (`VAULT_TIMEZONE`), not the host's local time.** Daily-note "today" is resolved in this configured IANA timezone (validated with `Intl.DateTimeFormat` at startup), so daily notes are correct regardless of where the process happens to run (Heroku dyno vs. a laptop).
- **`vault_batch_read` and `vault_batch_frontmatter_update` return a separate `failed[]` array** (path + error) distinct from `missing[]`. The reference collapses "not found" and "errored" into one bucket; splitting them lets the model distinguish "doesn't exist" from "exists but couldn't be processed" (e.g. a decode error) without parsing error text.
- **`vault_analytics_summary`/`vault_analytics_findings` take an explicit `refresh: boolean` flag.** Results are cached in-memory for 10 minutes; callers that need a guaranteed-fresh scan (e.g. right after a bulk edit) pass `refresh: true` instead of the cache silently going stale with no override.
- **Path policy rejects Obsidian/Windows-forbidden characters** (`: * ? " < > |`) in addition to the usual `..`/absolute-path traversal checks, so a path that would be unusable inside the actual Obsidian app is rejected at the tool boundary instead of silently succeeding server-side and breaking later in the client.
- **JSON Canvas node ids are 16 lowercase-hex characters** (`randomBytes(8).toString('hex')`) when `vault_canvas_add_node`/`vault_canvas_add_edge` omit an id, matching Obsidian's own id format rather than a UUID.

## Phase 1 — final fix wave (2026-08-28)

The whole-branch final review (`.superpowers/sdd/2026-08-28-phase-1-core-tools-localfs/final-review-report.md`) found two symlink-guard gaps and three unenforced result-size caps that landed in a short fix wave before Phase 1 was declared accepted:

- `softDelete` now checks the `.trash` destination with `assertInsideRoot` (a symlinked `.trash` could previously redirect a "deleted" file outside the vault), and `search()` validates `pathPrefix` once before dispatching to either the JS fallback or ripgrep (the ripgrep branch previously passed a raw absolute path straight to `rg`, which follows a symlinked root).
- `searchRipgrep` moved from buffered `execFile` to a streamed `spawn` + `readline`, stopping the child process once the result limit is reached instead of buffering the full (potentially unbounded) output; the ripgrep suite (skipped locally without `rg`) now also runs in CI (`.github/workflows/ci.yml` installs ripgrep via `apt-get`), and `scripts/docker-smoke.sh` exercises `vault_search` — so the production search path (rg installed, as in Docker) is verified rather than only the JS fallback.
- `vault_list`, `vault_search_frontmatter` and search match text are all capped (`MAX_LIST_ENTRIES`, `MAX_FRONTMATTER_HITS`, `MAX_MATCH_TEXT_CHARS` in `src/storage/limits.ts`) with a `truncated` flag, and `okJson` clamps its text block to `MAX_RESULT_CHARS` as a last line of defense — closing the 120k-char result-size budget gap on all three call paths.
- `DAILY_NOTES_FOLDER`/`DAILY_NOTES_FORMAT` are validated at startup (`loadConfig` renders `resolveDailyNotePath` once) instead of failing on the first daily-note tool call, and `toDateFnsFormat` accepts Obsidian's own moment-style default (`YYYY-MM-DD`) so pasting it in no longer requires knowing date-fns' different token casing.

**Deferred minors from the review, carried forward as Phase 2/3/4 follow-ups** (none blocking Phase 1 acceptance): a read-size guard for multi-hundred-MB files dropped directly on disk and per-error-code analytics labeling (Minor 7); windowed (offset/hasMore) reads for oversized notes, already scheduled as Phase 4 result-size windowing (Minor 8); NFC/NFD filename round-tripping once Drive is in the picture (Minor 11); the misleading `a:b` path-policy message ordering (Minor 12); more specific `IO` sub-errors for `ENOTDIR`/`ENAMETOOLONG` ancestors (Minor 13); a warning or refusal when `mergeFrontmatter` silently drops invalid existing YAML (Minor 14); cleaning up an orphaned directory when a folder-into-its-own-subtree move fails (Minor 15); a pre-decode size check on binary uploads and normalizing the echoed path on write (Minor 16); restricting canvas link-node URLs to `http(s)`/`obsidian:` (Minor 17); a cheap adapter `stat()` for daily-note existence checks, deferred to the Phase 3 Drive adapter work (Minor 18); a `*.tmp` sweep on startup (Minor 20); deterministic watcher-ready signaling instead of the fixed sleep in a couple of tests (Minor 21); and tighter `.max()` bounds on free-text tool arguments (Minor 23). Recommendations 1–6 (adapter `stat()`/`NoteMeta`-returning writes, per-tenant runtime resolution and the `FrontmatterIndex` LRU, per-(tenant,path) mutex, Drive search-semantics documentation, an explicit NFC/NFD Unicode policy) all target Phase 2/3 work where the relevant interfaces are introduced.

## Phase 2′ — final fix wave (2026-08-29)

The whole-branch final review (archived with the fix wave and the fix-later list in `../reviews/2026-08-29-phase-2-final-review.md`) found three blocking defects and six important ones, all fixed before Phase 2′ was declared accepted:

- **State reset was a no-op against a running app.** `revoke-all --reset` unlinked `state.json`, but `FileTokenStore.reloadIfChanged` treated a failed `stat` as "unchanged", so the app kept its in-memory document and the next `lastUsedAt` write recreated the file with every token. `--reset` now writes the empty v1 document atomically (`writeEmptyStateFile`), and a vanished file resets the in-memory document to empty.
- **Windows vault paths were mangled by Compose.** `.env` values containing a space or `#` were double-quoted, where compose-go expands `\a \b \f \n \r \t \v \\ \" \$` — `C:\Users\vanea\Obsidian Vault` did not survive. They are single-quoted now (literal in compose-go and Node `--env-file`), with an escaped double-quoted fallback for values containing an apostrophe.
- **A stale `public-url` file made `npm run up` print the previous tunnel URL** and the app boot twice. The supervisor removes the file before every quick-mode spawn, `runUp` only prints a URL two health polls 3 s apart agree on, and the app ignores `PUBLIC_URL_FILE` unless `TUNNEL_MODE=quick`.
- **Write amplification into the synced vault:** `lastUsedAt` is refreshed at most every 5 minutes instead of on every `/mcp` request; the instance heartbeat went 60 s → 5 min (staleness window 15 min); unauthenticated `/oauth/authorize` spam can no longer grow `pending` past 16 rows.
- **Failure modes:** an unreadable/corrupt store now rejects with `OAuthError(server_error)` and a log line instead of an opaque 500; `PUBLIC_URL` carrying a path prefix is rejected outright (it only ever half-worked) rather than producing a URL that authenticates but doesn't route.
- **Minors:** the Cloudflare token reaches cloudflared through `TUNNEL_TOKEN` rather than argv; one OAuth rate-limit bucket mounted once in `mountAuth`; `compose.yaml` defaults both services to `TUNNEL_MODE=quick`; the Docker healthcheck grace period covers the tunnel wait (`--start-period=130s`); the ripgrep search branch got the `_brainstem` exclusion test the JS fallback already had.

## Phase 2 — Auth (outline; spec §7, §8 — corrected 2026-08-28, see `../reviews/2026-08-28-auth-consistency-review.md`)

Interfaces this phase must honor from Phase 1: `RuntimeResolver = (ctx: McpRequestContext) => Promise<VaultRuntime>` (per-tenant runtime from `ctx.authInfo`), `createApp(config, logger, resolveRuntime)`, `AuthInfo` from the SDK (`clientId`, `scopes`, `expiresAt`, `resource`, `extra.userId`).

1. Postgres layer: `pg` pool (max 5), migrations runner, `schema.sql` for `users`, `google_tokens`, `vaults`, `oauth_clients`, `oauth_pending`, `oauth_codes`, `oauth_tokens`, `audit_events`; tests against `DATABASE_URL` (local Postgres via Docker or Heroku CI add-on).
2. `auth/crypto.ts`: AES-256-GCM seal/open with `ENCRYPTION_KEY`, SHA-256 token hashing, `randomToken()`; key never logged.
3. Resource server: `OAuthTokenVerifier` backed by `oauth_tokens` (hash lookup, expiry, **audience = mcpUrl**), `requireBearerAuth` on `/mcp`, `mcpAuthMetadataRouter` PRM (`resource`, `authorization_servers`, `scopes_supported: ['vault']`), 401 challenge shape test, token-passthrough test (Claude token never appears in outbound requests — assert via a mocked Google client).
4. AS metadata (`/.well-known/oauth-authorization-server`) built only from `PUBLIC_URL`, including `code_challenge_methods_supported: ['S256']`, `client_id_metadata_document_supported: true`, `authorization_response_iss_parameter_supported: true`, `token_endpoint_auth_methods_supported: ['none']`.
5. CIMD fetcher: SSRF guard (single DNS resolve + pinned connection → reject every RFC 6890 special-use range, HTTPS only, **no redirects at all**, 5 s timeout, **5 KB cap**, JSON media types only), `client_id` == URL string-for-string (explicit path required, port significant), required fields, shared-cache semantics (`s-maxage`/`max-age`/`Expires`, `no-store`/`private` ⇒ uncached), loopback redirect port-agnostic match (Claude Code). `cimd-ssrf.test.ts`.
6. DCR fallback (`/oauth/register`, JSON, public clients only, `application_type`, per-IP rate limit, 30-day expiry) behind `DCR_ENABLED`.
7. `/oauth/authorize`: validation (`response_type=code`, PKCE S256 required, `resource` == mcpUrl, `scope ⊆ {vault}`), `oauth_pending` row, **consent page** (client_name, redirect hostname, loopback warning) — never skipped; the consent `POST` is CSRF-bound to the pending row via a stored `nonce` (mismatch/replay ⇒ 400, row burned).
8. Plane B: Google code flow (`openid email drive.file`, `access_type=offline`, **two-step prompt**: `select_account` first, then `consent&login_hint=<sub>` only if the callback shows we hold no refresh token for that `sub` and Google returned none), `verifyIdToken` (`sub` = identity, `email` only if `email_verified`), encrypted refresh token storage, callback completes Plane A: mint code (≤60 s, single-use, bound to client/redirect/challenge/resource/user), redirect with `code`, `state`, `iss`.
9. `/oauth/token` (form-urlencoded only): code exchange with PKCE verification, access token 1 h + refresh 90 d; refresh **rotation** with family id, 60 s grace, reuse → family revocation, `invalid_grant` on dead tokens. No upstream calls. Plus `POST /oauth/revoke` (RFC 7009, revokes the family; `revocation_endpoint` advertised).
10. Tenancy: `resolveRuntime` maps `authInfo.extra.userId` → cached `VaultRuntime` (byte-bounded LRU, concurrency-safe); per-tenant token-bucket rate limit; `tenant-isolation.test.ts` with concurrent A/B requests including cache poisoning attempts. Phase 2 still uses LocalFS per tenant (`VAULT_PATH/<userId>`) so isolation is provable before Drive exists.
11. Audit log writer (`audit_events`) wired into every mutating tool; reads behind `AUDIT_INCLUDE_READS`.
12. Google `invalid_grant` → `users.reauth_required`, one tool error explaining the reconnect, **and revocation of the user's Plane A token families** so Claude's next refresh fails with `invalid_grant` and Claude itself prompts to reconnect (tested).
13. End-to-end acceptance, local first: Claude Code (`claude mcp add --transport http … http://localhost:3000/mcp`, CIMD + loopback) and MCP Inspector against the Docker Compose stack; then claude.ai web + Claude mobile against a public URL with public DNS (tunnel or Heroku — Claude rejects hostnames without a public IPv4 A record); refresh rotation observed after 1 h; all auth suites green.

## Phase 3 — GoogleDriveAdapter (outline; spec §4)

1. Drive client wrapper (`@googleapis/drive` + per-tenant `OAuth2Client` from the encrypted refresh token; access token cached ~55 min).
2. Vault bootstrap: find-or-create root folder by `VAULT_FOLDER_NAME`, persist folder id in `vaults.root_ref`, skeleton subfolders, `00-inbox/README.md` seed.
3. Path ↔ fileId map from one flat paginated `files.list` (`trashed=false`, fields incl. `parents`, `appProperties`), rebuilt on TTL/miss, patched on write/move/delete.
4. `read`/`batchRead` (`files.get` + `alt=media`), `write`/`writeBinary`/`append`/`edit` (`files.update` media upload, **no** `keepRevisionForever`), `appProperties` mirror of `type/domain/status`.
5. `list` from the map, `move` (`addParents/removeParents` + rename), `softDelete` to a `.trash` folder inside the vault root, `search` = `fullText contains` scoped to app files merged with index hits, `watch` absent (`Caps.watch=false`) → index TTL re-scan.
6. Truncated exponential backoff with jitter on 403/429; clean `VaultError('IO')` messages; quota-unit awareness in logs.
7. Contract test suite: the Phase 1 adapter tests re-run against a mocked Drive API (recorded fixtures) so both adapters satisfy the same `StorageAdapter` behavior; a manual live test against a real account.
8. `STORAGE_BACKEND=drive` default path in `main.ts`; Heroku config switched; end-to-end from Claude mobile: login → write → read/search → visible as `.md` in Drive.
